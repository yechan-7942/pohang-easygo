## 저장소 공유 업데이트

사용자가 커밋과 공개 원격 push를 명시적으로 요청했다.
최초 공유 대상은 기획·조사·검증·인수인계 문서와 Git 제외 규칙, 빈 환경변수 예시다.
아래의 '커밋·push하지 않았다'는 각 작업 당시 기록이다. 현재 반영 상태는 `git status -sb`, `git log -1`, 원격 HEAD를 확인한다.
실제 `.env`, 참가신청서 출력물, 원본·개인 데이터는 공유하지 않는다.

## 현재 단계

**데이터·API 조사 및 복지 API 최초 연결 확인 완료, 앱 구현 전.** 사용자가 로컬 `.env`에 키를 입력했고 두 API의 목록·상세 조회를 확인했다.
모든 기능을 한 번에 구현하지 않고 자료 확인부터 진행하기로 했다.
참가신청서·제안서 Word 작성본을 작성했다. 제출 전 참가자 정보 확인과 HWP/HWPX 형식 저장이 남아 있다.

## 확정한 기획

발달장애인의 포항 공공기관 이용을 준비·연습·현장 소통까지 돕는다.

| 홈 메뉴 | 첫 업무 |
|---|---|
| 신분증을 만들거나 다시 받고 싶어요 | 주민등록증 재발급 |
| 증명서를 받고 싶어요 | 본인의 주민등록등본 발급 |
| 복지 상담을 받고 싶어요 | 상담 목적 정리·방문 준비 |
| 도서관을 이용하고 싶어요 | 회원증 만들기 |

공통 흐름: 할 일 → 조건 확인 → 기관 선택 → 준비물 → 연습 또는 현장 안내 → 도움 요청.
기관·업무 선택 순서는 이용자 피드백에 따라 조정 가능하다.
핵심은 정보를 모아 두는 데서 나아가 실제 행동과 도움 요청을 지원하는 것이다.

## 조사 결과 요약

상세 근거·신청 링크는 `docs/data-api-research.md`와 `data/sources.json`에 있다.

- 먼저 신청할 후보: 지자체복지서비스 15108347, 중앙부처복지서비스 15090532.
- 위 2개는 복지 상담 참고자료를 보강하며 앱의 모든 메뉴를 제공하는 API는 아니다.
- 도서관 위치·운영 정보는 전국도서관표준데이터 15013109의 파일을 먼저 확인한다.

- 포항시 구술민원 목록에서 등·초본과 주민등록증 재발급 등을 확인했다. 실제 제공 방식은 기관에 확인해야 한다.

- API별 승인 방식·계정별 트래픽은 미확정. 키 발급 후 확인한다.
- 복지 API 최초 연결 결과는 `docs/api-verification-2026-11-13.md`에 있다. 파일 데이터 내려받기, 전체 페이지 수집, 현장·이용자 평가는 미실시다.

## 다음 작업

사용자가 API 인증키를 발급받았다고 알렸다. 내용은 공유받지 않았다.
루트 `.env` 입력 틀과 `.env.example`을 추가했다. 지자체/중앙부처 Decoding 키용 변수는 각각
`SSIS_LOCAL_WELFARE_SERVICE_KEY`, `SSIS_NATIONAL_WELFARE_SERVICE_KEY`다.
이후 사용자가 입력을 완료했고, 두 API 목록·상세의 HTTP 200 / API 0 SUCCESS를 확인했다. 키 내용을 출력하지 않는다.

1. 복지 API 2개 신청·키 입력·최초 연결 확인 완료. 검증 보고서를 읽고 다음 작업을 정한다. 키를 채팅으로 요청하지 않는다.
2. 키가 준비되기 전에도 전국도서관표준데이터의 실제 파일과 포항 레코드를 확인하고 원본·수집일·해시를 기록할 수 있다.
3. 포항의 시범 행정복지센터와 도서관을 각 1곳 선정할 근거를 조사한다. 실내 사진·창구·지원은 현장 확인이 필요하다.
4. 네 업무의 공식 근거와 미확인 항목을 구분한 콘텐츠 초안을 만든다. 아직 앱 전체를 만들지 않는다.
5. 승인 후 API의 목록·상세·지역 필터와 누락을 실제 호출로 검증한다.
6. 데이터 확인 후 화면 시안과 대표 업무 구현으로 넘어간다.
